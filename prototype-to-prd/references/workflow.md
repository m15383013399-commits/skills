# Prototype To PRD Workflow

一、输入分层

1、先读输出约束
1.1 `AGENTS.md`
1.2 用户补充的格式要求
1.3 已有文档模板

2、再读业务事实
2.1 项目说明
2.2 原型说明
2.3 已对齐的规则
2.4 现有系统参考口径

3、最后读原型材料
3.1 页面原型
3.2 交互稿
3.3 流程图
3.4 页面截图

二、标准步骤

1、先列页面清单
1.1 主页面单独列。
1.2 弹窗单独列。
1.3 抽屉单独列。
1.4 详情页单独列。
1.5 选择器、配置框、特殊空状态按独立功能点处理。

2、再画页面关系
2.1 从哪里进入。
2.2 点什么进入。
2.3 保存后回哪里。
2.4 关闭后回哪里。
2.5 是否刷新原列表或原详情。

3、先做一轮推演，不要马上写PRD
3.1 按主流程走一遍。
3.2 按异常流程走一遍。
3.3 按失败路径走一遍。
3.4 把走不通、不确定、互相冲突的点记下来。
3.5 按问题类别整理后分批问用户。

4、根据用户回答继续推演
4.1 每收到一轮回答，再跑一遍主流程。
4.2 再看按钮逻辑是否闭环。
4.3 再看上下游联动是否闭环。
4.4 再看状态流转是否闭环。
4.5 只有关键阻塞项收口后，才开始写文档。

5、按页面写第一版
5.1 页面结构。
5.2 交互说明。
5.3 字段与规则。
5.4 状态说明。
5.5 异常与边界。
5.6 本期不做 / 待确认。

6、按动作补第二版
6.1 每个按钮点完后发生什么。
6.2 每个切换动作后发生什么。
6.3 每个弹窗打开时带什么值。
6.4 每个保存、删除、停用、下发后状态怎么变。

7、按实现补第三版
7.1 默认值。
7.2 必填。
7.3 可编辑性。
7.4 校验规则。
7.5 联动规则。
7.6 覆盖规则。
7.7 历史影响。
7.8 前后端边界。

8、按风险补第四版
8.1 批量操作。
8.2 周期处理。
8.3 导入导出。
8.4 上传下载。
8.5 树形筛选。
8.6 名称唯一性。
8.7 状态流转。
8.8 关联关系。

9、最后做收口
9.1 删除空话。
9.2 删除背景型段落。
9.3 把抽象能力改成具体交互。
9.4 没法确认的不要写死。

三、写作原则

1、先写事实，再写判断。
2、先写动作，再写说明。
3、一条只写一个规则。
4、开发会问的问题，提前写。
5、测试能提用例的粒度，才算写到位。
6、用户没有回答清楚前，不急着起草正文。

四、默认判断

1、项目已通过 `AGENTS.md` 约束文风和格式时，不在流程里重复定义风格。
2、项目说明和原型说明负责提供事实，不在 skill 里写项目业务细节。
3、没有依据的规则不补。
4、必须落地但没有依据的规则，写 `待确认`。
